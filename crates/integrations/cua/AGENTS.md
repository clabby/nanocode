Keep the official provider's tool definitions unchanged. The default provider is ChatGPT.app's `@oai/cua-repl` launcher, the same `cua_repl` server Codex Desktop's unified-computer-use plugin starts, run with `CUA_REPL_ENABLED_SURFACES=computer`. It starts node_repl with the Sky service and replaces the generic node_repl tool descriptions with its computer use instructions, which is how every model, Claude included, learns from the `mcp__cua_repl__js` definition that it controls the desktop and that its first call is `cua.getState()` or `cua.getApp(...)`. Launching node_repl directly advertises only a generic JavaScript REPL. The provider's catalog is pinned in src/catalog.json as the `tools` array the launcher returns from MCP tools/list, so its tools and the prompt prefixes built from them are available at session build without starting the provider and stay identical across sessions. Regenerate the file from a live tools/list with the same environment when the provider changes. Each session starts the provider on its first call and compares the live catalog with the advertised one; a difference fails the call before anything is dispatched. A missing installation keeps the tools advertised, reports itself through ComputerConfig::unavailable, and fails each call with that error. Configurations built with ComputerConfig::new have no pinned catalog and discover theirs when they connect.

The client advertises form elicitation, because Sky asks for each app through `nodeRepl.createElicitation` ("Allow Computer Use to use \"Slack\"?") and fails the call when the client cannot answer. Nanocode runs with Codex's `danger-full-access` sandbox and `never` approval policy and has no approval prompt, so elicitations get the answer upstream Codex gives under that policy (codex-rs/core/src/session/mcp.rs): accept with empty content when the form requests no fields, decline everything else. Sky still refuses apps its own policy denies or forbids before asking.

Every call sends `_meta["openai/confirmation_policies"]` with `computer_use` and `browser_use` set to "No confirmation policy applies.", so the Computer Use documentation returned to the model omits the upstream Confirmations Policy (`@oai/cua/docs/tinysky-alt-confirmations.md`), which tells it to stop and ask the user before sending messages, deleting data, logging in and similar actions. Upstream replaces that document with any non-blank string up to 20,000 bytes and restores it for blank text, so the override must stay non-blank.

Validate complete Base64 media payloads before accepting them. MIME sniffing needs at most the 12-byte RIFF/WebP header, represented by the first 16 Base64 characters; decode only that prefix after validation.
