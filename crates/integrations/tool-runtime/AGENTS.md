Runner catalogs advertise provider-owned workspace routing; brains classify routed tools with installed backend policies first. Older runner catalogs without routing metadata need the backend's workspace policy on the brain or an upgraded runner.

Runner disconnect permanently revokes the registration and resolves its pending calls before awaiting socket teardown. Sent calls have an uncertain outcome; unsent calls are unavailable. Pool shutdown initiates every runner revocation and listener cancellation before its first await, so dropping a shutdown or disconnect future cannot strand calls behind an already revoked connection.

Remote Code Mode sockets derive liveness from the caller's SocketPolicy.request_timeout. Each side sends a WebSocket ping every half request_timeout. The connection closes only when a ping that was actually sent after the last inbound message stays unanswered for another half request_timeout, and the reader drains buffered traffic before the watchdog may fire. A stalled local scheduler therefore cannot fault a live peer, periodic pings cannot postpone detection, and a frozen peer is detected within request_timeout of its last traffic. Pending operations then report unknown outcomes without replay, and follow-up requests are not dispatched. Operation deadlines never close the connection themselves; cancellation cleanup after a deadline ends when the runner replies or the watchdog closes the socket.

RunnerPool accepts tool runners and remote Code Mode executors through the same connect and listen paths. The first frame decides the protocol: a catalog with `definitions` registers an executor in the pool's `CodeModeExecutors`, anything else continues as an attachment runner on the already open socket, so single-connection runners are never dialed twice. Connects through the runners tool and /runner fail fast instead of retrying. `RunnerPool::keep_connected`, used for runners configured at startup, redials with the attachment transport backoff until first contact, detects the protocol, and redials a Code Mode executor whose connection drops until it is disconnected explicitly; `Runner::start` keeps the attachment-only retry behavior. An executor without an explicit `Runner::name` uses the name it advertises. Incoming executors replace a registration that is not ready or that comes from the same advertised runtime id, which is how a hand reconnects; a different live executor with the same name is rejected with a policy close the executor prints. Explicit disconnect clears the sessions that selected the executor and revokes its runtime id, and the executor stops retrying when it reads that close. Pool shutdown closes executors without revocation so they reconnect when the brain returns.

`remote::Hand` is the hand side of the protocol. `Hand::connect(url, token, tools)` dials a brain and reconnects until the brain revokes it; `Hand::listen(address, token, tools)` accepts brains on a loopback address. A hand is a whole machine with a name, not a workspace: its name defaults to `Hand::machine_name()`, the sanitized host name, and its directory, the current directory by default, is only where cells start. `run` reports connection progress through `HandEvent` instead of printing. `nanocode::hand::connect` and `listen` add the default hand tools, Claude file tools from `ClaudeWorkspaceFiles::machine` that accept any path on the box plus the Codex workspace tools, and `nanocode hand <url>` wraps them.

Pool-managed hand sockets and `nanocode hand` use `SocketPolicy::runner()`: tungstenite's default 64 MiB message limit, which the pool's attachment sockets already accept, and a liveness window of twice the attachment heartbeat interval, so both sides ping every 20 s like attachment heartbeats. Operations and brain callbacks have no deadline unless the caller passes `call_timeout_ms`; liveness detects dead peers and pending work reports an unknown outcome. Executors that dial a brain reconnect with the attachment driver's transport backoff, reset after a connection outlives `STABLE_CONNECTION`. output/remote-hands/hands_probe.rs measures attach, failure detection, reconnect, revocation and exec round trips against real executor processes; copy it into crates/nanocode/examples to build it.
