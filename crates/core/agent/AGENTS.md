Own backend-independent agent handles, lifecycle, session and usage contracts. Keep durability orchestration, subagent registries, provider implementations and native host adapters out of this crate. Preserve the nanocode-agent compatibility reexports and native/WASM future behavior.

Turn::result consumes the turn and drops its private event receiver before awaiting completion. Result-only consumers should use it so unread mirrored events do not accumulate; streaming consumers can continue polling Turn and AgentEvents.

Pending durable turns: a turn left `TurnStatus::Pending` by a retryable failure or a host crash blocks different prompts with a Retry `OperationBlocked` error. Admission refuses a new operation while an unclaimed turn is pending and records nothing, so blocked prompts never become further pending turns; a pending turn claimed by a live attempt or queued admission does not block. An attempt that leaves its turn pending still emits a terminal run event so event observers settle. Hosts resume pending turns in accepted order and queue new input behind them, as nanocode does on resume and when a prompt is refused. List it with `SessionStore::turns(session_id)`. Replay it with `agent.prompt(PromptRequest::new(agent.decode_durable_prompt(turn.input)?).request_id(turn.id))`, which resumes the recorded operation and reports interrupted tool calls as unknown outcomes instead of repeating them. Abandon it by adding `.cancel_on_admission()`, which records the operation Cancelled without a model request. `Turn::cancel` and `cancel_active_turn` only target a live turn and cannot settle an operation pending from a failed attempt or an earlier process.

Shutdown stops a live prompt turn without settling it, as pi-durable `close()` stops invocations without writing outcomes: the operation stays pending, the turn result is `TurnStopped`, and reopening the session resumes it with interrupted tool calls reported as unknown outcomes. Only an explicit cancel records a turn Cancelled. Queued turns that never began and compactions are still cancelled at shutdown, so every operation left pending is a prompt turn that hosts resume. Subagent turns stopped this way become Interrupted and resume when their root is restored.

Two hosts may open the same session with the same backend. The latest opener acquires ownership and fences the other, whose durable writes are then refused, so turns there stop without settling and nothing is recorded twice. The new owner resumes pending turns, reporting tool calls the old owner had in flight as unknown outcomes. A fenced host surfaces the fence, as nanocode does by telling its window that the session moved and refusing further prompts until the user takes the session back with a fresh open.
