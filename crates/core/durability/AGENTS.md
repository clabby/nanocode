Own the portable StateStore interface, owner and revision contracts, durability errors, content-addressed payload encoding and deterministic state transitions. Keep agent handles, session drivers, checkpoint catalogs and host storage implementations out. Keep the journal state independent of session metadata; parameterize only checkpoint serialization so the state model compiles once before agent lifecycle contracts. Preserve serialization and content-addressing formats; runtime/durability reexports these contracts for existing consumers. Native store futures remain Send and WASM store futures remain local. Native owner IDs use the same UUIDv7 generator without pulling in an executor; WASM uses the installed platform host for time and randomness.

StateStore::acquire_with invokes its owned, synchronous StoreUpdate once against the acquired state. None acquires ownership without changing the revision; StoreReplacement advances the revision once and preserves immutable records. Callbacks only calculate data and must not perform external work. Existing adapters inherit acquire followed by a fenced replace; failures after successful acquisition are Backend errors because ownership already changed. Adapters may combine the owner and replacement writes, but must commit both before acknowledging success and preserve fencing, revision checks and uncertain outcomes. Native callbacks are Send; WASM callbacks may be local.

StateStore::acquire_with_companion acquires a distinct companion state together with acquire_with on the primary state and reports the whole operation. An equal companion is rejected with NotCommitted before any write. NotCommitted means neither state's owner or revision changed; any other error leaves both states uncertain. The default acquires the companion and then the primary, so failures after the companion acquisition are Backend errors. Adapters may combine both acquisitions and the replacement into one synchronized batch, validating both fences and revisions first and acknowledging success only after the entire batch is durable. A failed or interrupted batch may leave a prefix committed. StateStore::batches_companion_acquisition reports this batching capability and defaults to false; its value stays fixed for an adapter. Wrappers return true only when they forward acquire_with_companion to an adapter that does, because callers then defer the companion acquisition into the primary one instead of overlapping it with other work.
