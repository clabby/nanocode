Own the subagent task tree, its registry, harnesses, inter-agent messages and the durable subagent journal. Keep Tact's business logic, accepted-result handling, instruction revisions, residency and checkpoint recovery intact when changing storage.

The journal state `<root>:subagents` is format version 4. Its payload lists one content-addressed record key per agent and the tail of a chain of message pages; agent records, messages, pages and child checkpoints are immutable records, so a write stores only what changed. Versions 1 to 3 keep loading: inline agents and message key lists are read as before, and versions 3 and 4 load child checkpoints lazily. Older binaries reject version 4.

Each agent is stored as a small state record that references a profile record holding its descriptor, binding task, output schema and host context, so tool-call progress rewrites only the state record.

Every change to a ChildSession must go through Sessions::get_mut or Sessions::insert, which assign a fresh journal generation. The journal writer keeps the last committed record key for each agent by generation and checkpoint key, and each message key by message id, and reuses them without re-serializing; an agent is re-encoded only after a mutable access or a new checkpoint. Messages are immutable once created, so their keys are memoized; pages hold 64 message keys like runtime/durability paged sequences, and only pages after the first changed message are rewritten. The writer collects changed agents and new messages under the registry lock and serializes them after releasing it. A writer updates its cache only after the store acknowledged the save, so a failed save re-encodes everything it referenced. An agent record omits binding_task when it equals the descriptor task and stores a completed output once, marking last_output as equal to the Completed status.

SubagentStore::records_sessions and ChildJournalStore::records_children report whether record_session stores child checkpoints. When they are false, as for the runtime/durability journal, the registry keeps only the encoded checkpoint and skips recording children. Progress captures encode child checkpoints on a blocking thread on native targets and inline on WASM.
