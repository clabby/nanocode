Own backend-independent runtime assembly, agent ownership, durable recovery and subagent coordination. Receive provider construction and host services through interfaces. Keep substantial assembly outside generic public builders, and keep facade compatibility methods as thin forwards. Do not depend on backend or integration crates.

Ownership tracks agents and children as weak handles in ArcSwap lists and admissions in one atomic counter, without locks. Dropping every handle of an agent, its Agent clones and Turns, releases it; Claude turns already running finish, a Codex turn running then stops pending and resumes on the next open, and runtime shutdown reaches only agents that still have handles. Subagent completions for a released root wait for its next open. open, open_loaded, open_session and a durable resume serialize per session id: a concurrent open waits for the first, and an open that finds a live agent for the session returns that agent with a new Agent::subscribe stream instead of acquiring a second owner, which would fence the first. When that agent reported AgentStopped, TurnStopped or a Reopen disposition, or StateStore::owner shows another owner took the session, as when another process or runtime opened it, the open first reopens it in place. Adopted agents heal themselves the same way: a prompt or route refused with one of those errors before its turn started, or submitted after an earlier turn of the agent ended with one, rebuilds the backend from the store through AgentOwner::reopen, which this runtime serves while it is open and durable, swaps it under every existing handle, resumes the session's pending turns in accepted order, reusing the pending admission whose request ID or prompt matches the retried prompt, and retries once. Explicit shutdown or disconnect turns healing off. Turn events keep flowing to the existing streams; events the rebuilt backend publishes on its own are forwarded to them. A freshly opened agent receives the session's pending prompt turns; the first prompt or route resumes them in accepted order before its own request, and a prompt whose request ID names one of them resumes the earlier ones and then itself, so hosts that replay pending turns explicitly keep working and hosts that do not are no longer blocked by them.

AgentRuntime::open_loaded consumes an already loaded session through the configured store, preserving validation and ownership acquisition while avoiding another catalog load. SessionStore::prepare_resume_loaded validates its original store and identity; any backend preload must match the acquired checkpoint before reuse.

Hosts that drive durable turns by request ID classify a finished prompt with `AgentRuntime::durable_outcome`, which reads the configured store: completed, failed or cancelled once the store records it, replaying a turn the store records as completed by its request ID to recover its final message when the prompt itself returned an error, `Waiting` while an execution policy asks to retry later, and `Interrupted` when the host must reopen the runtime from its checkpoint. `pending_turns` and `durable_prompt` resume pending turns with their stored input, and `settle` reports a root quiescent with no pending turns after persisting its subagents, comparing activity revisions across the persist. `SessionEvents::start` merges a root's agent events and subagent updates into batches for an `EventSink`, coalesces consecutive assistant and reasoning-summary deltas of the same item, holds a batch that ends in a delta until the caller's window since the previous delivery elapses, and answers `drained` once everything received has been delivered. Drain requests reach the pump over a channel and the host spawns the returned future, so the pump holds no lock.

Validate WASM workspace paths with Path::has_root: wasm32-unknown-unknown uses root-based virtual paths, while std Path::is_absolute requires a prefix on that target and rejects /workspace. Keep relative paths invalid.

RuntimeBuilder::build_async awaits an optional RuntimeDefaults::default_store_async preparation before starting its dedicated construction thread. Native host defaults use the asynchronously admitted JSONL opener so cancelled builders waiting for one journal do not each allocate a parked construction thread and file descriptors. Custom defaults without this hook retain synchronous store construction on the dedicated thread; explicit caller stores bypass the hook. Keep build as the synchronous compatibility entry point. Cancelled construction must not keep Tokio runtime shutdown waiting on a journal lock. WASM construction remains local. Runtime shutdown awaits store flush after host and owned-agent shutdown, including their error paths, so native adapter caches can finish without blocking Drop.
