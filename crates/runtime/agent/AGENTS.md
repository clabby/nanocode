Own backend-independent runtime assembly, agent ownership, durable recovery and subagent coordination. Receive provider construction and host services through interfaces. Keep substantial assembly outside generic public builders, and keep facade compatibility methods as thin forwards. Do not depend on backend or integration crates.

Ownership tracks agents and children as weak handles in ArcSwap lists and admissions in one atomic counter, without locks. Dropping every handle of an agent, its Agent clones and Turns, releases it; Claude turns already running finish, a Codex turn running then stops pending and resumes on the next open, and runtime shutdown reaches only agents that still have handles. Subagent completions for a released root wait for its next open. open, open_loaded, open_session and a durable resume serialize per session id: a concurrent open waits for the first, and an open that finds a live agent for the session returns that agent with a new Agent::subscribe stream instead of acquiring a second owner, which would fence the first. An agent that reported AgentStopped, TurnStopped or a Reopen disposition is shut down and replaced. A freshly opened agent receives the session's pending prompt turns; the first prompt or route resumes them in accepted order before its own request, and a prompt whose request ID names one of them resumes the earlier ones and then itself, so hosts that replay pending turns explicitly keep working and hosts that do not are no longer blocked by them.

AgentRuntime::open_loaded consumes an already loaded session through the configured store, preserving validation and ownership acquisition while avoiding another catalog load. SessionStore::prepare_resume_loaded validates its original store and identity; any backend preload must match the acquired checkpoint before reuse.

Validate WASM workspace paths with Path::has_root: wasm32-unknown-unknown uses root-based virtual paths, while std Path::is_absolute requires a prefix on that target and rejects /workspace. Keep relative paths invalid.

RuntimeBuilder::build_async awaits an optional RuntimeDefaults::default_store_async preparation before starting its dedicated construction thread. Native host defaults use the asynchronously admitted JSONL opener so cancelled builders waiting for one journal do not each allocate a parked construction thread and file descriptors. Custom defaults without this hook retain synchronous store construction on the dedicated thread; explicit caller stores bypass the hook. Keep build as the synchronous compatibility entry point. Cancelled construction must not keep Tokio runtime shutdown waiting on a journal lock. WASM construction remains local. Runtime shutdown awaits store flush after host and owned-agent shutdown, including their error paths, so native adapter caches can finish without blocking Drop.
