Own session drivers, shared store actors, child journals and checkpoint catalogs over the core/durability contracts. Keep storage adapters out.

SessionStore::session, SessionStore::resume and DurableSession::open, open_shared, open_shared_described and open_sibling acquire ownership and fully persist the described record before returning, so callers observe the session in the catalog and fence earlier owners at return. Preserve these semantics.

SessionStore::prepare_session, SessionStore::prepare_resume and DurableSession::prepare_shared_described return a driver without acquiring ownership or writing to the store; prepare_resume validates the existing state and infers its record through non-fencing reads. The first command acquires ownership once through StateStore::acquire_with, merging the prepared record and, for acquire_agent_with_initial, the initial settings. The native JSONL adapter commits both with one full disk sync; adapters using the default fallback commit acquisition and replacement separately. Use prepared sessions only where backend construction consumes them immediately, such as runtime/agent spawn, fork and resume pipelines and backend lazy child executions, so agent construction stays fully synced before the agent is returned. Acquisition failures go to the triggering command; uncommitted failures may be retried and other failures poison the driver.

DurableSession::acquire_agent_with_initial_checkpoint commits a backend's initial checkpoint in the same acquisition replacement as the prepared record and initial settings, only when the stored state has no session record, checkpoint or operations; otherwise it returns InitialAcquisition::Existing and leaves the state as a plain acquisition would. Backend harnesses use it for fresh prepared sessions and fall back to their eager durability path for every Existing outcome, including records without a checkpoint or pending operations, so saved model and initial settings remain authoritative. DurableSession::described_record returns the record supplied at preparation without acquiring and is not proof that the state is empty.

Startup durability is bounded by full disk syncs, about 5 ms each with F_FULLFSYNC on macOS APFS. Measure journal entries, sync count and latency for new-session construction when changing acquisition paths.
