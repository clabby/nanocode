Own backend-independent tool selection, registration and execution here. Depend only on core and runtime crates. Keep provider schemas and handlers in backends, and concrete MCP, remote socket and process adapters in integrations. Preserve nanocode-tool-runtime compatibility reexports and native/WASM host contracts.

Remote Code Mode executors are dynamic placements, not tool definitions. `CodeModeExecutors` in nanocode-code-mode owns connected executor hosts and per-session selections; it compiles for WASM and is itself a `CodeModeHost` for hosts without a local evaluator. A session resolves its own selection, then its root session's (linked through `Tools::for_session`), then the replacement default, then this machine. A selection is one hand, a list of hands, or every connected hand; lists and every-hand selections run each exec cell on all their hands concurrently, label each hand's output `[hand <name>]`, prefix nested call ids with the hand name, and report a hand of the list that is not connected as a failed section. A broadcast wait resumes the same cell on every hand, translating the requested cell id through the per-hand ids parsed from each hand's `Script running with cell ID` status. A selected executor that is not connected fails the cell without dispatching anything; never fall back to another machine. Executor failures, including unknown outcomes after a dropped connection, are failed cell outputs rather than host errors, so losing a hand never aborts the brain's turn. The native runtime keeps its evaluator for local placements and routes exec to the selected executor with the brain's non-workspace Code Mode tools as callbacks, excluding names the executor serves. Wait goes to the most recent placement with a running cell from that session and probes the next placement only when a cell is not found. Turn and cancellation controls reach every executor the session used. Direct workspace tools of a session placed on an executor return an error instead of running locally. Model-visible tool definitions stay unchanged when placements change.

Code Mode nested calls on one tool runtime pass through a read/write gate, as Codex's parallel_execution lock gates its tool calls. A tool that a backend's CodeModeToolPolicy marks exclusive waits for running calls to finish and blocks new calls while it runs; every other tool shares the gate with concurrent calls. Backends mark tools that mutate workspace files exclusive (Claude Write, Edit and NotebookEdit, Codex apply_patch), so an edit cannot interleave with a shell command or another edit started from the same cells, while independent reads and commands keep running concurrently. The span records the admission kind and wait time.
