Own backend-independent tool selection, registration and execution here. Depend only on core and runtime crates. Keep provider schemas and handlers in backends, and concrete MCP, remote socket and process adapters in integrations. Preserve nanocode-tool-runtime compatibility reexports and native/WASM host contracts.

Remote Code Mode executors are dynamic placements, not tool definitions. `CodeModeExecutors` in nanocode-code-mode owns connected executor hosts and per-session selections; it compiles for WASM and is itself a `CodeModeHost` for hosts without a local evaluator. A session resolves its own selection, then its root session's (linked through `Tools::for_session`), then the replacement default, then this machine; the selection is the one machine its scripts run on. A selected executor that is not connected fails the cell without dispatching anything; never fall back to another machine. Executor failures, including unknown outcomes after a dropped connection, are failed cell outputs rather than host errors, so losing a hand never aborts the brain's turn. The native runtime keeps its evaluator for local placements and routes exec to the selected executor with the brain's non-workspace Code Mode tools as callbacks, excluding names the executor serves. Wait goes to the most recent placement with a running cell from that session and probes the next placement only when a cell is not found. Turn and cancellation controls reach every executor the session used. Direct workspace tools of a session placed on an executor return an error instead of running locally. Model-visible tool definitions stay unchanged when placements change.

Hands are chosen per tool call, not per script. A nested call whose object arguments include `hand` loses that field and runs on the named hand through the registry's `HandCalls`, unless the name is the machine running the script; freeform tools take `{ input, hand }`, and a bare `{ input }` is accepted as freeform input. On a brain `HandCalls` is `CodeModeExecutors::calls`, which runs the call through `CodeModeHost::call` and counts the hand as used by the session; on a hand it is a callback to its brain, which forwards the call. Such calls skip the local admission gate, pass the target's own gate, and report a missing hand or a lost connection as that call's error, so `Promise.all` across hands settles each call on its own. `CodeModeExecutors::tool` is the `hands` tool, which lists attached hands and where the calling script runs and documents the `hand` argument.

Code Mode nested calls on one tool runtime pass through a read/write gate, as Codex's parallel_execution lock gates its tool calls. A tool that a backend's CodeModeToolPolicy marks exclusive waits for running calls to finish and blocks new calls while it runs; every other tool shares the gate with concurrent calls. Backends mark tools that mutate workspace files exclusive (Claude Write, Edit and NotebookEdit, Codex apply_patch), so an edit cannot interleave with a shell command or another edit started from the same cells, while independent reads and commands keep running concurrently. A shared call holds the gate until it finishes or until its cell yields to the model, as a Codex exec_command releases parallel_execution when it returns at its yield time while the process keeps running: Code Mode reports each yield, each resumed observation and each cell's end through `CodeModeToolset::cell_observed`, the registry drops the shared admissions of a yielded cell's running calls, and calls that cell starts while yielded wait for running exclusive calls and then release. Exclusive calls keep their admission until they finish. Before this, an Edit in a later cell waited 272 s and 394 s for long shell commands whose cells had yielded. The span records the admission kind and wait time.
