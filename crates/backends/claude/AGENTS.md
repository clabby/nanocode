# Claude upstream contracts

- Own Claude harness construction and tool installation here. Bash executes through core/process interfaces; native constructors remain compatibility defaults. Runtime assembly supplies host process executors.
- File tools use the workspace as their relative-path base, not an authorization boundary. Accept host-accessible absolute paths, parent traversal and symlinks consistently with Bash. Keep exact-match editing, concurrent-change checks, atomic replacement and caller output budgets; do not add workspace-only or arbitrary file-size/search caps. Attach workspace guidance only for targets within that workspace.

- `client/` (`nanocode-backend-claude-client`) owns the Messages protocol types, `ClaudeClient`, authentication, subscription wire compatibility and transport; this crate re-exports it at the crate root. `upstream::VERSION` reuses the client's pinned CLI version.
- The native default client prefers the nanocode login in `<nanocode home>/claude.json`, written by `ClaudeHomeLogin` for `/login claude`, and falls back to the Claude Code login. Its file host serializes compare-and-swap through a sibling `.lock` file and replaces the store atomically.
- `tools/` (`nanocode-backend-claude-tools`) owns independent provider tool definitions and handlers; keep it independent of clients, agent lifecycle, runtime and durability. Preserve this backend's public tool paths through re-exports.
- Preserve the exact identity and core text blocks in `prompts/claude-code-system.json`, with version and official package integrity recorded in `prompts/upstream.json`.
- Keep provider blocks unchanged. Add Code Mode and environment/project context as separate blocks. Preserve explicit caller system overrides.
- Load global and project instructions once per session through `nanocode_home`, like codex-rs, and send them as one `# AGENTS.md instructions` system block. Tool results never carry instruction context.
- Use `upstream::tool_definition` for verified provider contracts. `tools/src/tools/upstream.json` records exact names, descriptions and schemas from the official CLI; provenance selects the capture profile for each definition. Bash uses the expanded profile with Glob and Grep available.
- Run `python3 scripts/verify-claude-upstream.py --capture` with the pinned official macOS ARM64 CLI installed to verify fresh requests against a local stub and dummy credentials. `--write` refreshes the pinned artifacts after review. `--offline` compares existing ignored captures and artifact hashes without running the CLI.
- Keep captures, package archives and dynamic request context under ignored `output/claude-upstream-parity`. Never copy captured workspace paths, Git state, credentials or user configuration into provider assets.
- Keep authentication, billing and cache policy separate from prompt/tool provenance. Subscription requests preserve tool names and the SDK identity instead of adding underscore aliases or a second identity.
- Keep recursive shared tool schemas intact and use non-strict direct tool sampling for them; Claude strict tool sampling rejects reference cycles. Runtime input and output-contract validation still applies.
- Captured contracts do not install host capabilities. TaskOutput, TodoWrite, Skill, shared Code Mode and durable delegation remain explicit SDK additions; do not describe their custom schemas as captured upstream contracts.
- Keep the captured catalog limited to supported tool adapters. Agent, plan-mode, notebook editing, user-question, worktree, cron, workflow and upstream-only messaging, reporting and wakeup tools are omitted. Preserve retained upstream descriptions unchanged, including references to omitted tools.
- Root sessions on the subscription wire use the 1-hour cache TTL and subagents and side conversations keep the 5-minute default, matching Claude Code 2.1.299, which selects 1h for subscriber main-thread and SDK requests. A 1h request upgrades every system cache breakpoint to 1h because 1h breakpoints must precede 5m ones.
- Compaction requests keep the turn's system prompt, tools and tool choice and append the compaction instruction, because Anthropic invalidates the cached message prefix when tool_choice changes. Only a summary attempt that calls tools anyway is retried with tool_choice none under its own durable step.
- `ClaudeWorkspaceFiles::new` reports workspace-relative results when possible. `ClaudeWorkspaceFiles::machine` and `hand_tools` report absolute paths. Both constructors accept host-accessible paths, use their directory for relative paths and default searches, follow write-target symlinks and create parent directories. Tool names, descriptions and schemas are unchanged.
