# Codex upstream contracts

- Own Codex harness construction and reserved built-in tool names here. Tool handlers execute through core/process interfaces; native constructors remain compatibility defaults. Runtime assembly supplies host process executors.

- `client/` (`nanocode-backend-codex-client`) owns the Responses protocol, model configuration, authentication, transports and pinned base prompts; this crate re-exports it as `client` and keeps `OpenAi`/`OpenAiBuilder` so backend registration impls stay local.
- Preserve the exact prompt bytes and extraction provenance in `client/prompts/upstream.json`.
- Keep the immutable provider prefix on `ModelConfig::base_system_prompt`; place runtime identity and additional instructions in developer context. Preserve the public composed `system_prompt()` compatibility view and explicit system overrides.
- `upstream/tools.json` pins the reviewed standard tool sources, local artifacts, and selected upstream option profile. Re-audit affected contracts against that revision before updating artifact hashes.
- Run `python3 scripts/verify-codex-upstream.py` from the repository root to verify upstream hashes, prompt extraction, local artifact integrity, and exact patch grammar. `--offline` uses the ignored `output/codex-upstream-parity` cache. Without `--serialize`, this verifies artifacts without executing Rust tool serialization.
- Add `--serialize` to execute the pinned upstream standard tool builders in an ignored minimal consumer binary. `--consumer-dump PATH` compares its five serialized contracts against a public SDK consumer JSON dump containing `codex_standard`. The harness preserves upstream handler bodies, schema types and selected wire serializers while omitting unrelated host dependencies.
- Keep output schemas as host metadata, matching upstream omission from Responses tool serialization.
- Local `web.run`, `image_gen.imagegen`, attachment, and delegation functions are SDK extension contracts. Do not describe them as upstream provider server tool parity. Host routing and shared Code Mode can decorate or transform model-visible exposure independently of the pinned standard definitions.

## Responses gateways

- `client::transport::ResponsesGateway` routes the unchanged Codex Responses request (prompts, tools, input items, `client_metadata`) to third-party Responses endpoints on native and WASM. `OpenAiBuilder::responses_gateway` applies its base URL and vendor model prefix, and selects stateless HTTPS full replay with store: false and no warmup. Without it, the ChatGPT and OpenAI API defaults are unchanged. The Chat Completions `ChatGateway` is separate and native-only; a config may use only one of the two.
- Only Sol, Luna and Astra are served, because these gateways forward the OpenAI Responses shape to OpenAI models. Cloudflare's Codex integration documents the same limit: https://developers.cloudflare.com/ai-gateway/integrations/coding-agents/openai-codex/. Route GLM, Kimi and MiMo through `ChatGateway`.
- OpenRouter: `POST https://openrouter.ai/api/v1/responses`, `Authorization: Bearer` with the OpenRouter key, `openai/<model>` IDs. Optional `X-OpenRouter-Title` and `HTTP-Referer`. Routing goes in the body `provider` object. The endpoint is stateless and rejects `store: true` and `previous_response_id`. Docs: https://openrouter.ai/docs/api_reference/responses/overview, https://openrouter.ai/docs/api_reference/authentication, https://openrouter.ai/docs/guides/routing/provider-selection.
- Vercel AI Gateway: `POST https://ai-gateway.vercel.sh/v1/responses`, `Authorization: Bearer` with an AI Gateway API key or Vercel OIDC token, `openai/<model>` IDs. Routing goes in body `providerOptions.gateway`. Responses WebSocket mode at `wss://ai-gateway.vercel.sh/v1/responses` is documented for OpenAI models, one model per connection, with a 4 MiB frame limit, so WebSocket is opt-in only for Vercel. Docs: https://vercel.com/docs/ai-gateway/sdks-and-apis/responses, https://vercel.com/docs/ai-gateway/sdks-and-apis/responses/websockets, https://vercel.com/docs/ai-gateway/authentication-and-byok, https://vercel.com/docs/ai-gateway/models-and-providers/provider-filtering-and-ordering.
- Cloudflare unified REST API (`ResponsesGateway::cloudflare`): `POST https://api.cloudflare.com/client/v4/accounts/{account}/ai/v1/responses`, `Authorization: Bearer` with a Cloudflare API token holding Workers AI Read, `openai/<model>` IDs, and optional `cf-aig-gateway-id`. Docs: https://developers.cloudflare.com/ai-gateway/usage/rest-api/.
- Cloudflare provider-native OpenAI endpoint (`ResponsesGateway::cloudflare_gateway`): `POST https://gateway.ai.cloudflare.com/v1/{account}/{gateway}/openai/responses` with bare OpenAI model IDs. `Authorization` carries the OpenAI key or a Cloudflare token for Unified Billing. `cf-aig-authorization` authenticates an Authenticated Gateway, and `cf-aig-byok-alias` selects a stored key. `OpenAiAuth::gateway_managed()` omits `Authorization` so stored keys apply, and requires `gateway_token`. Cloudflare's WebSocket API is Realtime-only, so this path is HTTPS-only. Docs: https://developers.cloudflare.com/ai-gateway/usage/providers/openai/, https://developers.cloudflare.com/ai-gateway/configuration/authentication/, https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/, https://developers.cloudflare.com/ai-gateway/usage/websockets-api/realtime-api/.
- WASM `HostTransport::http` implementations must forward every `HostConnectRequest::headers()` entry. They must send `Authorization: Bearer` only when `sends_bearer_token()` is true. Native HTTPS applies the same headers.
- Gateway routing covers Responses inference. Built-in `web__run` and `image_gen__imagegen` adapters return an explicit unsupported result before authentication or network access under a Responses gateway; callers can register their own adapter tools. Preserve their advertised definitions. Codex inline compaction is supported only through the Cloudflare provider-native proxy; the translating gateways reject it before sending a request.

The macOS timezone fast path accepts only an absolute /var/db/timezone/zoneinfo/ symlink whose name appears verbatim as a zone or link in the system tzdata.zi index. Keep TZ/TZFILE overrides, GMT/UTC parser cases and every unrecognized layout on iana-time-zone. Verify first-request and initial-checkpoint date/timezone parity and fallback behavior when changing it.

Check cached WebSocket liveness before selecting incremental input. Replacing a closed socket must replay full history without consuming a model retry or backoff. If a cached socket closes during dispatch, replace it within the attempt only when the pump proves the request was not dispatched; a new connection failure or uncertain delivery keeps ordinary retry reporting. HostConnection::is_closed defaults to false for compatibility; host adapters may return true only when they know their connection is closed. Keep connection events and reconnect statistics for routine idle replacement.

The Responses API documents a 60-minute connection lifetime and the `websocket_connection_limit_reached` rejection at https://developers.openai.com/api/docs/guides/websocket-mode. Renew a reused connection within the same attempt only when this exact top-level error is its first response event. Replay full context without `previous_response_id`, preserve raw API and reconnect telemetry, and consume no model retry or backoff. A fresh replacement failure, response progress before expiry, terminal quota errors, and unrelated API errors retain ordinary failure handling. The external consumer at `output/connection-renewal-20261018/expiry.py` exercised these seven cases across 56 processes; routine-expiry warnings fell to zero, with local fixture median second-turn latency falling from 969 ms to 12 ms.

Each agent opens its Responses WebSocket in the background when its driver starts, using a connect-only attempt that sends no request; the first model call waits on the connection lock and reuses that socket. The `generate: false` warmup is opt-in through `websocket_warmup(true)`. Measured on gpt-6-luna (output/cache-probe, nc exec and a TUI prompt typed 3 s after start, median of 4-6 runs): the warmup added 11.4K input tokens per session and moved first output from 2.05 s to 2.51 s in exec mode, while background connect gave 1.71 s in exec mode and 1.37 s in the TUI against 2.23 s with the warmup. A warmed first call reached first output about 0.2 s sooner than a preconnected one, which does not cover the warmup's own round trip and tokens.

Track each connection's age with the portable monotonic clock and replace it before dispatch once it reaches the documented 60-minute lifetime. Check again before encoding and sending in case the deadline passes during dispatch preparation. Use full replay on the replacement. The standalone WASM consumer at `output/connection-renewal-20261018/wasm-consumer` exercises just before, exactly at, and after the lifetime boundary, plus reactive expiry, with a virtual clock and a one-attempt policy; all cases complete without a model retry.

Managed native ChatGPT refreshes use the persistent auth-file .lock sidecar across processes, acquired off the async executor before reloading credentials and held through refresh and atomic persistence. Do not unlink the sidecar: replacing it would split ownership. Login persistence uses the same lock. Synchronous logout reports a busy lock rather than blocking an executor that may be driving the refresh. Recheck the stored authorization after the token response so a concurrent external credential change is not overwritten. Keep retry jitter tied to the request thread identity so independent sessions do not retry in lockstep, and preserve server-directed delays.

Async ChatGPT auth paths run auth-file reads, parsing, serialization and fsync on the blocking pool and never hold the in-memory state lock across disk I/O. The managed refresh runs as a spawned task that owns the in-process refresh mutex, so a cancelled caller cannot discard a rotated refresh token; the sidecar lock moves into the blocking save and is released only after the atomic rename. Managed auth state is an immutable `ArcSwap` value carrying the prebuilt snapshot and token expiry, so request-path snapshot reads take no lock and decode no JWT; only the serialized refresh task replaces it. The cross-process sidecar lock still serializes refresh-token use and is not lock-free. The synchronous loader, status and logout functions remain blocking calls for synchronous callers.
